# A cleanup that recognised every carrier except the ones it was written for

**Severity:** 🟡 low · **Date:** 2026-10-20

## Symptom

`.gemini/commands/*.toml` — four generated carriers belonging to a client engram dropped on
2026-10-18 — were still in git, still advertising four skills, in a repository whose `sync` reported
clean and whose `doctor` reported healthy.

`sync` names five retired sink directories (`.pi/skills`, `.claude/skills`, `.cursor/skills`,
`.github/prompts`, `.gemini/commands`) and is supposed to empty every one of them. Running the pruner
against this repository's own tree returned `would remove: []` for all five.

## Root cause

The generated-marker test was anchored to column 0:

```ts
const GENERATED_HEADER_RE = /^<!-- engram:generated --> generated by engram from \S+/m;
```

Every Markdown carrier begins with a bare `<!-- … -->`. A TOML carrier cannot — `#` is that format's
comment marker — so the generator wrote

```
# <!-- engram:generated --> generated by engram from .ai/skills/audit.md — do not edit; run `engram sync`
```

and `^<!--` matched none of them. The retired-dir loop therefore classified every `.toml` carrier as
hand-written and skipped it, forever, while printing nothing. This is the failure mode the loop's own
comment warns about ("the safety property … is the generated-marker check"), inverted: a *safety* check
that silently returns false is indistinguishable from "no generated files here".

The existing regression test is why nobody caught it. It wrote

```ts
await sb.write('.gemini/commands/handoff.toml', marker);   // the bare HTML comment
```

— a shape the generator **never emits**. The test asserted that the pruner recognises a file that
cannot exist, and passed for every commit since the retired-dir branch was added.

## Fix

- `GENERATED_HEADER_RE` no longer anchors to the line start: the marker may sit inside a comment
  prefix. The rest of the stamp (`generated by engram from <path>`) is still required, which is what
  keeps a hand-written carrier whose prose merely *quotes* the marker out of reach.
- The test now writes the byte-for-byte shape the generator produces, backticked suffix included.

## Guard

- `test/commands.test.ts` → *REGRESSION a retired carrier dir is pruned whatever filename shape it
  holds*, with the TOML prefix in the fixture. Verified by reverting the regex: the test fails
  (`✖`), and passes again when restored — a fixture that reproduces the defect rather than one that
  was written beside it.
- `engram sync` on this repository now prints `pruned .gemini/commands/*.toml` ×4 and removes the
  empty directory.

## The generalisable rule

> Test fixtures must be produced by the code under test, not typed by hand. A hand-written fixture
> encodes the author's idea of the output; when the generator disagrees, the test silently starts
> asserting about a file the system cannot produce — and stays green while the feature is dead.
