# Architecture

## 1. Purpose

`engram` is a **project memory bank and scaffolder** for AI coding tools. It gives a repository one
portable memory directory (`.ai/`) plus one contract per tool, so context survives session ends and
survives switching tools. It is a **CLI, not a daemon**: no background process, no server, no
telemetry, zero runtime dependencies.

Explicitly out of scope: agent frameworks, RAG/indexing, MCP servers, hosted sync, editing the
user's code. The tool writes Markdown and reads Markdown.

## 2. Stack

| Layer | Technology | Version | Why this one |
| --- | --- | --- | --- |
| Runtime | Node.js (ESM only) | ≥ 20 | ships with every AI tool environment; `node:test` needs no dependency |
| Language | TypeScript | 5.7 | strict types over string-templating logic; `verbatimModuleSyntax` keeps the build honest |
| Build | `tsc` only | — | no bundler, no plugin chain, nothing to keep in sync |
| Tests | `node:test` + `node:assert` | — | test runner ships with the runtime; zero dev-deps beyond `typescript` + `@types/node` |
| Templates | TypeScript string builders in `src/templates/` | — | keeps `.tsc` output self-contained; no file-copy step at install time |
| Dependencies | none at runtime | — | a scaffolder that pulls a dependency tree into every consumer repo is a bad neighbour |

## 3. Repository map

| Path | Responsibility | Touches |
| --- | --- | --- |
| `src/cli.ts` | argv parsing, command dispatch, human output | everything (thin only) |
| `src/core/project.ts` | fs helpers, slug/date utils, project detection | nothing above it |
| `src/core/memory.ts` | reads `.ai/`, parses entries and `CURRENT_TASK.md` | `core/project.ts` |
| `src/core/fingerprint.ts` | builds the ≤1.5 KB fingerprint under a byte budget | `core/memory.ts` |
| `src/templates/contract.ts` | the machine-owned `.ai/` contract block, idempotent wrapping | nothing |
| `src/templates/ai-files.ts` | `.ai/` skeleton files and `_TEMPLATE.md` shapes | `contract.ts` conventions only |
| `src/templates/skills.ts` | the four canonical skill specs | nothing |
| `src/templates/meta-prompt.ts` | bootstrap meta-prompt generator | adapters, project facts, skills |
| `src/adapters/index.ts` | per-tool registry: rule files, skill sinks, style guides | templates only |
| `src/adapters/rules.ts` | renders rule files and refreshes contract blocks | `templates/contract.ts` |
| `src/adapters/skills.ts` | materialises canonical skills into tool-native carriers | `templates/skills.ts` |
| `src/commands/*.ts` | `init`, `dump`, `new`, `sync` orchestration | core + adapters + templates |
| `test/*.test.ts` | node:test suites against compiled output | everything |
| `.ai/` | this project's own memory bank (dogfooding) | generated by `engram init` |

## 4. Core topology

```text
cli.ts ──► commands/*  ──► adapters/*  ──► templates/*
              │               │
              └──► core/*  ────┘   (core never imports commands or adapters)
```

```text
init  : detect project → render .ai/ skeleton → render rule files + contract
        → materialise skills into tool sinks → write .engram/BOOTSTRAP.md
sync  : read existing rule file → refresh contract block in place → re-materialise skills
dump  : load .ai/ → parse CURRENT_TASK + entries → fit sections to byte budget → render
new   : render one memory file from the shared section skeleton
```

Dependency rule: `core/` is the leaf layer. `commands/` may use anything. `templates/` never reads
the filesystem. `adapters/` never reads the filesystem (only `commands/` pass content in). This is
what makes the whole pipeline testable in memory.

## 5. Invariants

1. **The contract block is machine-owned.** No human or model text ever lives between
   `<!-- engram:contract:start -->` and `<!-- engram:contract:end -->`; `sync` rewrites it in place.
   The splice has exactly one implementation (`replaceContractBlock` in `templates/contract.ts`),
   it ignores markers inside fenced code blocks, and it refuses to act on an unpaired marker.
   **Enforced:** `test/templates.test.ts`.
2. **`engram dump` never exceeds `--max-bytes` (default 1500), in UTF-8 bytes.** Content is dropped
   by section priority, then by line, then by a byte-boundary-safe hard cut. `truncated` is `true`
   whenever *anything* was left out, so the CLI never reports "under budget" while having silently
   dropped the binding decisions. **Enforced:** the `REGRESSION` cases in
   `test/fingerprint.test.ts`, including `maxBytes: 0`.
3. **`init` never clobbers human content.** Existing rule files keep their body *and* their
   frontmatter keys; only the contract block, the managed marker and the shared-reader note are
   regenerated. A narrowed `globs` scope or `alwaysApply: false` is never promoted. `--force` is
   required to replace a body. **Enforced:** `test/templates.test.ts`; an unpaired marker aborts
   the whole operation rather than guessing a slice.
4. **Canonical skills live once**, in `.ai/skills/*.md`. Tool carriers are generated and marked.
5. **Zero runtime dependencies.** `package.json` `dependencies` stays absent. **Enforced:** a test
   asserts the field is `undefined`.
6. **One decision per file, one topic per file.** Filenames are `YYYY-MM-DD-<kebab-topic>.md`.
7. **`_`-prefixed files are inert**: templates and examples, skipped by `dump` and `sync`.

## 6. Boundaries and known debts

- **No editor-side integration yet.** `dump` is pasted manually; a Claude Code hook or Pi extension
  that injects it automatically is the obvious next layer, and is deliberately out of v0.1.
- **Adapters encode each tool's conventions as of writing, and those conventions move.** Cursor
  `.mdc`, Windsurf triggers and Copilot `applyTo` all change; a review already found six stale or
  invented claims. Vendor knowledge lives in **two** places by design, and both must change
  together: the tool record (paths, skill sinks, style guide) in `TOOLS` in
  `src/adapters/index.ts`, and the frontmatter dialect in `frontmatterFor()` in
  `src/adapters/rules.ts`. `test/architecture.test.ts` fails if this section stops naming both.
  `engram tools` prints the inventory.
- **Vendor facts are not machine-checkable.** Each claim was verified against vendor docs by hand
  during review; nothing re-verifies them, so they rot silently. A scheduled re-check (or an
  `/audit` step that re-reads the docs) is a candidate for a later version.
- **`dump` parses Markdown heuristically.** A deliberately broken `CURRENT_TASK.md` degrades the
  fingerprint; it never throws. Unreadable paths (EACCES, a `.ai` file where a directory belongs)
  are reported as `readErrors` on stderr rather than being reported as "no decisions".
- **No `engram doctor`.** Drift detection today lives in the `/audit` skill spec, i.e. in the model,
  not in the CLI. A machine version is a candidate for v0.2.
