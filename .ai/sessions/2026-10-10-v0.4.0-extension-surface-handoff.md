# v0.4.0 — extension surface, and the adversarial round that reshaped it

**Status:** ✅ ACCEPTED · **Date:** 2026-10-10

## What was built

`.ai/` stopped being a fixed schema. A project can now add an L2 partition by declaring it in
`.ai/sections.json`, and a skill by dropping `.ai/skills/<name>.md` — neither requires an engram
release, and neither touches anything engram regenerates. See
`.ai/decisions/2026-10-10-project-declared-sections-and-skills.md` for the decision, the three-zone
model and the rejected alternatives.

## The review round, and why it mattered

Four independent adversarial reviewers ran against the change (back-compat/data-safety, test
quality, code quality, black-box CLI). They confirmed the core claims — the v1 contract block is
byte-identical, `sync` is idempotent, no hostile `sections.json` escapes the repo or crashes — and
then found **eleven real defects**, several of which the author's own probing had missed:

| # | Defect | Why it was invisible |
| --- | --- | --- |
| 1 | `sync` overwrote a file **outside** the repo through a symlinked carrier | the pruner next door *had* a `realpath` guard, which read like coverage |
| 2 | `.ai/` present but `.ai/skills/` gone ⇒ sync deleted every carrier | the guard keyed on `.ai/`, not on the canonical directory |
| 3 | One unparseable skill file ⇒ that skill's carriers deleted everywhere | "did not parse" was treated as "was deleted" |
| 4 | A newline in `trigger` injected a contract marker ⇒ unbounded rule-file growth | `inspectMarkers` reported `balanced` throughout |
| 5 | A hand-written carrier that merely *mentioned* the marker was deleted | substring test instead of a header test |
| 6 | The sections `dump` line evicted `PITFALLS`/`RECENT`/`BINDING` | appended to the never-dropped section |
| 7 | A section named `decisions` hijacked `engram new` | only the *singular* verbs were reserved |
| 8 | `"version": "1"` rejected as "unsupported version 1 — expected 1" | — |
| 9 | BOM in `sections.json` silently disabled **every** declared section | `parseSkillFile` stripped a BOM; this path did not |
| 10 | CRLF frontmatter matched nothing (`.` does not match `\r`) | the parser looked correct at a glance |
| 11 | The "byte-identical contract" test was a **tautology** | `AI_CONTRACT` *is* `aiContract()` |

Defects 9–11 are the most instructive. 9 and 10 are encoding bugs that only appear on input a
different editor produces; 11 is a test that asserted a function equals itself, so it would have
stayed green through any change to the block it claimed to protect. It now pins the v1 bytes by
sha256 (`d1df4b2e…`, 2126 bytes) and asserts that stripping the extension rows reproduces them
exactly.

## Two pitfalls worth carrying forward

- `.ai/pitfalls/cases/symlink-escapes-the-project-root.md` — a guarded operation beside an unguarded
  one is half a fix. Grep for the *sink* (`fs.writeFile`, `fs.rm`), not the call site that prompted
  the fix.
- `.ai/pitfalls/cases/new-line-evicts-elastic-content.md` — appending to whatever section is already
  never-dropped silently promotes the newest, least-important line above all elastic content.

## Accepted consequence

The `dump` sections pointer is **best-effort**. It sits in its own elastic tier and is dropped before
`PITFALLS`/`RECENT`/`BINDING`, so on an over-budget bank (`research` is one) it does not appear. The
guarantee is the contract block in the rule files, which is unbudgeted and always carries the rows.
`dump` reports `truncated: true` when it drops anything.

## Verification at hand-off

- `npm test` — **147 pass, 0 fail**; `npm run typecheck` clean.
- `engram dump` 1415 B (budget 1500); `engram sync` clean on this repo and on `/data/dev/research`.
- The v1 block digest was independently reproduced from `git show HEAD:src/templates/contract.ts`.
- The `core/` layering guard was **vacuous** (`/^(\.|node:)/` accepted every relative specifier, so
  it was green while `core/` violated the rule twice). It now rejects `../` and requires an explicit
  allowlist; the two pre-existing edges are recorded as debt in `.ai/ARCHITECTURE.md` §6.
